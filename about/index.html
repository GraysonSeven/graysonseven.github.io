02 // HOW I THINK

UNDERSTAND FIRST.
BUILD SECOND.

Whether the thing is software or mechanical, I prefer to understand how the parts interact before changing them. That makes it easier to solve the real problem instead of only treating the visible symptom.

03 // WORK STYLE

MAKE IT REAL EARLY.

I would rather build a working version, test it and improve it than spend too long polishing an idea that has never been used. Real feedback exposes weaknesses much faster than theory.
